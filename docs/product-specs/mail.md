# お客様へのメールの下書きと通知

管理者がお客様に送るメールの文面と、下書きの扱い。後ろの2つの節は、システムが自動で送る受付通知と、管理者への新しい申込の通知（送る部品の形は [notifications.md](../design-docs/notifications.md)）。下書きを作る操作は [booking.md](booking.md) の「確認メール」、管理 API の形は [admin-api.md](../design-docs/admin-api.md) の「下書き（3回目）」。

関連する不変条件: INV-6, INV-7, INV-10（[core-beliefs.md](../design-docs/core-beliefs.md)）

## 下書きの送り方

- 下書きは、管理者が Gmail（`studiozebra1st@gmail.com`）から送る。システムからは送らない
- 管理画面は、下書きを開くと、あて先・件名・本文をテンプレートから作って表示する。本文は、色と下線のついた見た目のまま、Gmail に貼れるようにコピーできる。件名とあて先もコピーできる
- 文面を直すときは、Gmail に貼ったあとで直す。管理画面には文面の入力欄を持たない。直した文面はシステムに残らない
- 送ったら、管理者が管理画面で下書きを「送信済み」にする。送らないことにした下書きは「送らない」にする。どちらにしたあとも、未送信に戻さない（ユーザーの判断）
- 未送信の下書きは、作った順に一覧で見られる。送信済み・送らないにしたものは一覧から消え、予約の詳細でだけ見られる
- 文面は、下書きを開いたときの予約の内容で作る。下書きを作ったあとに予約を変えたら、変えたあとの内容になる。下書きに差し込む値（キャンセル料など）は、下書きを作ったときの値を使う
- メールアドレスのない予約の下書きは、あて先を空にして、「メールアドレスがありません」と表示する。電話で伝えたら「送信済み」、伝えないなら「送らない」にする
- 本予約の承認と昇格の下書きでは、「同意書を Gmail で添付する」と表示する。同意書の PDF はシステムでは扱わない

理由（Gmail から送る）：送ったメールとお客様の返信が Gmail にまとまり、今の運用のまま使える。文面を直すのも、同意書を添付するのも、いつもの Gmail でできる。システムがお客様に送るのは受付通知（INV-6 の例外）だけになり、確認せずに送る経路がなくなる。

理由（文面を残さない）：文面にはお客様の個人情報が入る。送ったメールは Gmail に残るので、システムに複製しない（INV-10 の考え方）。

### 例

| 状況 | 操作 | 結果 |
|---|---|---|
| 未送信の下書き | 管理者が「送信済み」にする | 送信済みになり、未送信の一覧から消える。予約の詳細には残る |
| 未送信の下書き | 管理者が「送らない」にする | 送らないになり、未送信の一覧から消える |
| 送信済みの下書き | 管理者が「送らない」にする | 不可（未送信の下書きだけ変えられる） |
| 送らないにした下書き | 管理者が「送信済み」にする | 不可 |
| 承認の下書きを作ったあとに、予約の日時を変えた | 承認の下書きを開く | 文面は変えたあとの日時になる |

## 下書きのテンプレート

### 差し込む値

| 印 | 中身 |
|---|---|
| `{氏名}` | お客様の氏名 |
| `{担当者名}` | 管理者の名前。本番の設定で渡す（リポジトリには書かない）。設定がなければ「（担当者名）」と出す（管理者が Gmail で直す） |
| `{署名}` | メールの最後の署名（住所・電話・メール・HP）。本番の設定で渡す（リポジトリには書かない）。設定がなければ、署名の行を出さない（Gmail の署名を使う場合） |
| `{予約日時}` | 予約区間。下の「日時の書き方」 |
| `{利用時間}` | 予約区間の長さ。下の「日時の書き方」 |
| `{撮影内容}` | 選んだ撮影内容を「・」でつなぎ、撮影詳細があれば後ろに（）で付ける。撮影内容がなく撮影詳細だけなら撮影詳細だけ、どちらもなければ「-」 |
| `{人数}` | ご利用人数 |
| `{カメラマン}` | カメラマン氏名に「様」を付けたもの。なければ「-」 |
| `{機材保険}` | 付けていれば「ご付帯」、付けていなければ「-」 |
| `{仮予約の期限}` | 仮予約の期限（利用日の7日前の18時）。「10月13日(火)の18時」の形 |
| `{キャンセル料}` | 取消の下書きに差し込んだキャンセル料。「5,500円（ご利用料金の50%）」の形 |

- 撮影内容の名前は、申込フォームと同じ（スチール撮影、ムービー撮影、楽器の演奏を伴う撮影）。並びはこの順
- 日時はすべて JST で書く（INV-7）

### 日時の書き方

- 件名は「{予約日時}の…（スタジオゼブラ）」の形にそろえる（ユーザーの判断）。`{予約日時}` は本文と同じ書き方
- `{予約日時}`：「2026年10月20日(火) 15時00分〜17時00分」。時は0を付けず、分は2桁。曜日は半角の括弧で (月)〜(日) の1文字（例と同じ）
- 終わりが開始の次の日なら、終わりの前に「翌」を付ける（「22時00分〜翌2時00分」）。0時ちょうどに終わるときも「翌0時00分」
- `{利用時間}`：「2時間」「2時間30分」

### 強調の書き方

テンプレートの中の `<赤>…</赤>`、`<青>…</青>`、`<下線>…</下線>` は、コピーする本文で、その部分を赤字・青字・下線にする。印そのものは本文に出さない。

- 色は Gmail の文字色の赤（`#ff0000`）と青（`#0000ff`）。HTML では `<span style="color:#ff0000">`・`<span style="color:#0000ff">`・`<span style="text-decoration:underline">` にする

### 共通の部分

テンプレートの中の「（ご予約内容）」「（注意事項）」「（結び）」の行は、ここに書いた中身に置き換える。

**ご予約内容**（本予約の承認・昇格・変更で使う）

```
◇ ご予約内容 ◇
ご予約日時：{予約日時}（{利用時間}）
撮影内容：{撮影内容}
ご利用人数：{人数}名様
カメラマン様：{カメラマン}
機材保険：{機材保険}
```

**注意事項**（本予約の承認・昇格で使う）

```
◆ 注意事項 ◆

〈ホリゾントの床面が露出した状態でご利用の場合の注意事項〉

・<赤>撮影当日に履いていらっしゃった靴のご使用は禁止です。</赤>
　被写体の方の靴は別途ご用意いただき、新品・内履きにかかわらず
　養生テープでの養生をお願いします。
　※ガムテープや色付きのビニールテープはご使用不可。
　※やむを得ず、当日履いてきた靴をご使用になる場合は、¥550(税込)／1足にて
　 ご使用可能とさせていただきます。

・<青>撮影者様・スタイリスト様など、ホリゾント内にお入りになる方は</青>
　<青>デニム等の色落ちするボトムの着用をお控えください。</青>

・<下線>ブーツなど、ソール部分が厚い靴</下線>はホリゾントを著しく汚損する恐れがございますので
　ポージングの際には十分ご注意ください。

〈その他〉

・ご予約時間の5分前よりご入室いただけます。
　ご退室時は現状復帰をお願いいたします。
　なお、ご予約終了時間を5分以上超過した場合は、追加料金が発生いたします。

・スタジオ専用の、駐車場・駐輪場のご用意はございません。
　近隣のコインパーキングや公共の駐輪場等をご利用ください。
　<赤>※スタジオが入っている建物周辺への駐輪は厳禁です。</赤>

・スタジオのある建物内および周辺の路上は禁煙です。
　防犯カメラ等により喫煙が確認された場合、建物の管理人より連絡が入り
　撮影が中断となる可能性がございますのでご注意ください。

・ご利用料金は、ご利用当日に現金またはクレジットカードにてお支払いください。
```

- ホリゾントの注意事項は、養生の有無にかかわらず、いつも書く（当日に養生をやめることもあるため。見出しが「露出した状態でご利用の場合」なので、養生ありのお客様にも意味が通る）

**結び**（どのテンプレートも最後に付ける）

```
{担当者名}

--
{署名}
```

- `{署名}` の設定がなければ、「--」の行から下を出さない

### 昇格（仮予約から本予約へ）

件名：{予約日時}の本予約を承りました（スタジオゼブラ）

本文は「承認（本予約）」と同じ。ただし「この度はスタジオ利用のお申し込みをありがとうございます。」を「ご利用のご決定のご連絡をありがとうございます。」に、「本予約を承りました。」を「仮予約から本予約に切り替えました。」にする。

| 繰り上げの案内、残っている仮予約が1件 | 「すぐには繰り上げができません」の2行がある |
| 繰り上げの案内、残っている仮予約がない | 「すぐには繰り上げができません」の2行がない |
| 本文の `<赤>撮影当日に履いていらっしゃった靴のご使用は禁止です。</赤>` | コピーする本文では、その文が赤字になる。テキストの本文には印が出ない |
| `{署名}` の設定がない | 本文は `{担当者名}` の行で終わる（「--」の行がない） |
| メールアドレスのない予約の下書き | あて先は空で、「メールアドレスがありません」と表示する |
| UTC で保存した予約区間 2026-10-20T06:00Z–08:00Z | ご予約日時は「2026年10月20日(火) 15時00分〜17時00分」（JST で書く。INV-7） |


## 受付通知

フォームから申込を受け付けたときに、お客様へ自動で送るメール（INV-6 の例外）。この節のテンプレートは、人がレビューしたものだけを使う。

- 送るのは、フォームからの申込（本予約・仮予約・第二キープ）を受け付けたときだけ。管理者の直接入力では送らない。断った申込（締め切り・空き判定など）でも送らない
- 送信元は `noreply@studiozebra-1st.com`、返信先は `studiozebra1st@gmail.com`（[TECH_STACK.md](../TECH_STACK.md)）。お客様が返信すると Gmail に届く
- あて先は、申込フォームのメールアドレス
- 予約の成立・金額・空きの可否は書かない（INV-6）。申込の種類と希望の日時は、お客様が入れたものとして書く。「確定していない」ことをはっきり書く
- テキストだけのメール（色や下線は使わない）
- 日時の書き方は、下書きと同じ（「日時の書き方」）
- 送れなかったとき（SES の障害、あて先の誤りなど）も、申込は受け付けたままにする。送れなかったことは、エラーの種類だけをログに残す（ユーザーの判断。お客様の画面には受付番号が出ていて、申込は管理画面の承認待ちにも出るため）。ログから管理者に知らせる仕組みは、AWS の準備のときに作る
- 申込の処理の中で、申込を保存したあとに送る（ユーザーの判断）。送り終えてから、お客様の画面に受付番号を返す

件名：{予約日時}のお申し込みを受け付けました（スタジオゼブラ）

```
{氏名}様

この度はスタジオゼブラへお申し込みいただき、ありがとうございます。
下記の内容で、お申し込みを受け付けました。

受付番号：{受付番号}
お申し込みの種類：{申込の種類}
ご希望の日時：{予約日時}（{利用時間}）

お申し込みの内容を確認のうえ、担当者からあらためてご連絡いたします。
このメールの時点では、ご予約はまだ確定していません。

お問い合わせの際は、受付番号をお伝えください。
このメールは自動でお送りしています。ご返信いただくと、スタジオゼブラの担当者に届きます。

--
{署名}
```

- `{申込の種類}`：本予約・仮予約・第二キープ
- `{署名}`：下書きと同じ設定（`MAIL_SIGNATURE`）。設定がなければ、「--」の行から下を出さない
- 担当者名は書かない（自動で送るメールなので）

理由：今の予約フォームも自動返信を送っており、お客様が申込の到達を確かめられるようにするため（booking.md「確認メール」）。受付番号があれば、問い合わせのときに管理者がすぐに予約を開ける。

### 例

| 申込 | 送るメール |
|---|---|
| 本予約 2026/10/20 15:00–17:00 をフォームで受け付けた。氏名「架空 花子」、受付番号 ABCD2345 | あて先はフォームのメールアドレス。件名は「2026年10月20日(火) 15時00分〜17時00分のお申し込みを受け付けました（スタジオゼブラ）」。本文に「架空 花子様」「受付番号：ABCD2345」「お申し込みの種類：本予約」「ご希望の日時：2026年10月20日(火) 15時00分〜17時00分（2時間）」「ご予約はまだ確定していません」がある |
| 仮予約 2026/10/20 22:00–10/21 02:00 を受け付けた | 「お申し込みの種類：仮予約」「ご希望の日時：2026年10月20日(火) 22時00分〜翌2時00分（4時間）」 |
| 第二キープを受け付けた | 「お申し込みの種類：第二キープ」 |
| 締め切りを過ぎた申込を断った | 送らない |
| 管理者が直接入力した | 送らない |
| 本文に金額・「確定しました」・空きの有無の文がない | 受付通知のどの文面にもない（INV-6） |
| SES に送れなかった | 申込は受け付けたまま（201 と受付番号）。ログにはエラーの種類だけが出て、あて先や氏名は出ない |
| `{署名}` の設定がない | 本文は「スタジオゼブラの担当者に届きます。」の行で終わる |

## 管理者への新しい申込の通知

フォームから申込を受け付けたときに、管理者へ自動で送るメール。管理者あてなので INV-6 の対象外。

- 送るのは、受付通知と同じとき（フォームからの申込を受け付けたとき）だけ
- あて先は、設定（`MAIL_ADMIN_TO`）のメールアドレス。設定がなければ送らない
- お客様の個人情報（氏名・会社名・メールアドレス・電話番号・住所・カメラマン氏名・自由記述の欄）を書かない。管理画面の予約の詳細へのリンクだけを書く（INV-10）
- 管理画面の URL は、設定（`ADMIN_APP_URL`）から作る。設定がなければ、リンクの代わりに「管理画面の承認待ちを確かめてください」と書く
- 送れなかったときは、受付通知と同じく、申込は受け付けたままにし、エラーの種類だけをログに残す

件名：新しいお申し込みがあります（スタジオゼブラ）

```
新しいお申し込みがありました。管理画面で内容を確かめ、承認か却下をしてください。

{予約の URL}
```

### 例

| 申込 | 送るメール |
|---|---|
| フォームで申込を受け付けた。`MAIL_ADMIN_TO` と `ADMIN_APP_URL`（http://localhost:5174/）がある | あて先は `MAIL_ADMIN_TO`。件名は「新しいお申し込みがあります（スタジオゼブラ）」。本文に予約の詳細へのリンク（http://localhost:5174/#/reservations/{予約の id}）がある |
| 同上 | 本文・件名に、お客様の氏名・メールアドレス・電話番号・撮影の内容がない（INV-10） |
| `MAIL_ADMIN_TO` がない | 管理者への通知は送らない（受付通知は送る） |
| `ADMIN_APP_URL` がない | リンクの代わりに「管理画面の承認待ちを確かめてください」と書く |
| 管理者への通知だけ送れなかった | 申込は受け付けたまま。受付通知は送る |

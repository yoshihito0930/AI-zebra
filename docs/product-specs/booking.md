# 予約・空き判定の仕様

関連する不変条件: INV-1, INV-2, INV-3, INV-4, INV-6, INV-7（[core-beliefs.md](../design-docs/core-beliefs.md)）

日時はすべて Asia/Tokyo（JST）で書く。保存はUTC（INV-7）。

## 用語

| 用語 | 意味 |
|---|---|
| 予約区間 | お客様がスタジオを使う時間帯。`[start, end)` の半開区間 |
| バッファ | 片付けのための時間。予約区間の**後ろに1時間**。管理者は予約ごとに30分に縮められる |
| 占有区間 | 予約区間にバッファを足した区間 `[start, end + バッファ)`。空き判定にはこちらを使う |
| 利用日 | 予約区間の開始日時の、JSTでの日付。日付をまたぐ予約でも開始日 |
| 仮予約の期限 | 利用日の7日前の 18:00（JST）。お客様はこの時刻までに本予約にするかを決める。仮予約申込もこの時刻まで |
| 承認待ち | お客様が申込み、管理者がまだ承認していない状態。仮予約申込と本予約申込がある |
| 仮予約 | 利用日の7日前まで枠を押さえるための予約。管理者の承認で成立する。本予約への昇格と取消は管理者が手で行う |
| 本予約 | 利用を確定させる予約。キャンセル料の対象 |
| 第二キープ | 仮予約と重なる時間を希望するお客様の、順番待ちの予約。枠を確保する（仮予約とだけ重なってよい） |
| 深夜帯 | 23:00〜翌8:00。それ以外（8:00〜23:00）を通常帯と呼ぶ |
| ブロック枠 | 予約以外の理由（休業、メンテナンス、Googleカレンダーから取り込んだ予定など）で枠を塞ぐもの。管理者が入れるか、Googleカレンダーから取り込む。後ろにバッファを付けられる |

> 「仮予約」は以前「管理者がまだ承認していない予約」の意味で使っていたが、スタジオの業務上の意味（キャンセル料なしの仮押さえ）に合わせて改めた。承認前の状態は「承認待ち」と呼ぶ。

## 営業時間と予約できる時間帯

- 24時間営業。予約はどの時刻にも入れられる
- 料金は、通常帯（8:00〜23:00）が通常料金、深夜帯（23:00〜翌8:00）が深夜料金（「料金」の節）
- 営業時間と料金の区分は、今後変わる可能性がある

## 時間の単位と利用時間

- 開始・終了は30分単位（JSTの毎時 :00 か :30）
- 最短2時間、最長24時間
- ただし、予約区間が少しでも深夜帯にかかる予約は、最短4時間
- 日付をまたぐ予約もできる
- 判定はJSTで行う（INV-7）。同じ時刻なら、どのタイムゾーンで表した日時が渡されても結果は同じ

理由：30分単位は、利用時間を細かく選べるようにするため。最長24時間は、深夜帯を含めた利用に対応しつつ、1件の予約で確保する枠の数を DynamoDB の1トランザクションに収めるため（[TECH_STACK.md](../TECH_STACK.md)）。

### 例

| 申込の予約区間 | 結果 |

| 10/20 10:30–13:00 | 予約可 |
| 10/20 10:15–12:15 | 予約不可（30分単位でない） |
| 10/20 10:00–11:30 | 予約不可（2時間未満） |
| 10/20 03:00–07:00 | 予約可（深夜帯にかかり、ちょうど4時間） |
| 10/20 03:00–05:00 | 予約不可（深夜帯にかかり、4時間未満） |
| 10/20 23:00–10/21 02:30 | 予約不可（深夜帯にかかり、4時間未満） |
| 10/20 06:00–09:00 | 予約不可（通常帯にもかかるが、深夜帯にかかるので最短4時間） |
| 10/20 05:00–09:00 | 予約可（深夜帯にかかり、ちょうど4時間） |
| 10/20 21:00–23:30 | 予約不可（深夜帯に30分かかり、4時間未満） |
| 10/20 21:00–23:00 | 予約可（23:00で終わるので深夜帯にかからない） |
| 10/20 08:00–10:00 | 予約可（8:00から始まるので深夜帯にかからない） |
| 10/20 22:00–10/21 02:00 | 予約可（日付をまたぐ。利用日は10/20。深夜帯にかかり、ちょうど4時間） |

| 10/20 10:00–10/21 10:30 | 予約不可（24時間を超える） |

| 10/20 10:00–12:00 を UTC（10/20 01:00–03:00）で渡す | 予約可（UTCの時刻では深夜帯にかかるが、判定はJST） |

## 予約の状態

```
仮予約申込 → 承認待ち（仮） ─(承認)→ 仮予約 ─(管理者が昇格)→ 本予約
本予約申込 → 承認待ち（本） ─(承認)→ 本予約
承認待ち ─(却下)→ 取消
仮予約・本予約 ─(取消)→ 取消

第二キープ申込 → 承認待ち（第二キープ） ─(承認)→ 第二キープ
第二キープ ─(重なる仮予約が取消 → お客様の承諾 → 管理者が繰り上げ)→ 仮予約
第二キープ ─(重なる仮予約が本予約に昇格)→ 終了
第二キープ ─(辞退・返事がない → 管理者が取消)→ 取消
```

| 状態 | 占有区間の枠を確保するか |
|---|---|
| 承認待ち（仮・本・第二キープ） | する（承認前でも、重なる申込は受けない） |
| 仮予約 | する |
| 本予約 | する |
| 第二キープ | する（仮予約とだけ重なってよい） |
| 取消・終了 | しない（確保していた枠は解放する） |

- 承認待ちは自動では失効させない。古いものや開始が近いものは、管理画面で警告する。理由：管理者は数人で、意図しない枠の解放を避けたい

## 空き判定

- 申込の占有区間が、既存の承認待ち・仮予約・本予約・第二キープ・ブロック枠のどの占有区間とも重ならないとき、予約可能
- 結果として、予約と予約の間は必ず1時間以上空く
- 区間はすべて半開区間で扱う。`[09:00, 13:00)` と `[13:00, 16:00)` は重ならない
- 第二キープの申込だけは、仮予約1件との重なりを許す（「第二キープ」の節）
- 公開APIが返すのは、時間帯ごとの「空き／第二キープ可／空きなし」だけ。誰の予約か、どの種類の予約かは返さない（INV-3）

理由：バッファを後ろだけにすると、バッファ同士の重なりを考えずに済み、「占有区間は互いに重ならない」という単純な不変条件（INV-1）のまま、予約の間を1時間にできる。

### バッファを30分に縮める

- 管理者は管理画面で、予約ごとに後ろのバッファを1時間か30分に切り替えられる。お客様は選べない
- 切り替えると占有区間が変わるので、枠の確保・解放を伴う変更として扱う（INV-2）
- 30分から1時間に戻すときも空き判定を通す。延びる30分に他の予約があれば戻せない（INV-1）
- 公開APIの空き状況は、各予約の実際の占有区間から計算する

#### 例

| 状況 | 操作・申込 | 結果 |
|---|---|---|
| 本予約 A 09:00–12:00、バッファ1時間（占有区間 09:00–13:00） | 申込 12:30–14:30 | 不可（12:30–13:00が重なる） |
| 同上 | 管理者が A のバッファを30分にする | 成功。占有区間は 09:00–12:30 になる |
| A のバッファ30分（占有区間 09:00–12:30） | 申込 12:30–14:30 | 予約可（12:30で接するだけ） |
| A のバッファ30分、本予約 B 12:30–14:30 あり | 管理者が A のバッファを1時間に戻す | 不可（12:30–13:00が B と重なる） |

### 例

以下、バッファはすべて1時間とする。

既存の本予約が 09:00–12:00 の場合、占有区間は 09:00–13:00。

| 申込の予約区間 | 申込の占有区間 | 結果 |
|---|---|---|
| 13:00–15:00 | 13:00–16:00 | 予約可（13:00で接するだけ。間は1時間） |
| 12:30–14:30 | 12:30–15:30 | 予約不可（12:30–13:00が重なる） |
| 04:00–08:00 | 04:00–09:00 | 予約可（09:00で接するだけ） |
| 04:30–08:30 | 04:30–09:30 | 予約不可（09:00–09:30が重なる） |
| 05:00–09:00 | 05:00–10:00 | 予約不可（09:00–10:00が重なる） |

既存の予約が承認待ち・仮予約・第二キープでも、結果は同じ。

日付をまたぐ場合：既存の本予約が 10/20 22:00–10/21 02:00 なら、占有区間は 10/20 22:00–10/21 03:00。

| 申込の予約区間 | 結果 |
|---|---|
| 10/21 03:00–07:00 | 予約可 |
| 10/21 02:30–06:30 | 予約不可（02:30–03:00が重なる） |
| 10/20 18:00–21:00 | 予約可（占有区間 18:00–22:00。22:00で接するだけ） |
| 10/20 18:00–21:30 | 予約不可（22:00–22:30が重なる） |

## 申込の締め切り

- 受付期間の上限はない（何日先でも申込める）
- 本予約申込は、開始の24時間前まで
- 仮予約申込は、仮予約の期限まで。期限を過ぎたら本予約申込だけを受け付ける
- ちょうど境界の時刻は「過ぎた」側に入れる（半開区間の考え方に揃える）

理由：24時間前までにすると、管理者が承認する余裕がある。

### 例

開始が 10/20 15:00 の場合、仮予約の期限は 10/13 18:00、24時間前は 10/19 15:00。

| 申込日時 | 本予約申込 | 仮予約申込 |
|---|---|---|
| 10/13 17:59 | 受付 | 受付 |
| 10/13 18:00 | 受付 | 不可（期限を過ぎた） |
| 10/19 14:59 | 受付 | 不可 |
| 10/19 15:00 | 不可（ちょうど24時間前） | 不可 |

開始が 10/21 00:30 の場合（利用日は10/21）、仮予約の期限は 10/14 18:00、24時間前は 10/20 00:30。

## 仮予約から本予約へ

- 仮予約は自動では本予約にならず、失効もしない。管理者がお客様に確認し、管理画面で本予約に昇格させるか、取消す（今と同じ運用）
- 本予約に昇格させたら、お客様への通知の下書きを作る。管理者が確認してから送る（INV-6）
- 仮予約の期限を過ぎても仮予約のままのものは、管理画面で警告する
- 期限の時点でまだ承認待ちの仮予約申込も、状態を変えない。管理画面で警告し、管理者が本予約として承認するか、却下するかを決める

理由：管理者は利用日の6日前ごろにお客様へ確認の連絡を入れており、その結果で昇格か取消を判断している。時刻で状態を自動で変えると、この確認と食い違うおそれがある。

### 例

仮予約 10/20 15:00–19:00（仮予約の期限は 10/13 18:00）の場合。

| 時刻・操作 | 結果 |
|---|---|
| 10/13 17:59 | 仮予約のまま |
| 10/13 18:00 | 仮予約のまま。管理画面で警告する |
| 10/14 管理者が本予約に昇格 | 本予約。通知の下書きができる |
| 10/14 管理者が取消 | 取消。キャンセル料なし（仮予約のため） |
| 承認待ちのまま 10/13 18:00 を過ぎる | 承認待ちのまま。管理画面で警告する |

## 第二キープ

- 優先順位は「仮予約 → 第二キープ → 第二キープより後の申込」
- 第二キープの申込にも、管理者の承認が必要。承認待ちの段階から枠を確保する
- 第二キープの占有区間が重なってよいのは、承認済みの仮予約の占有区間だけ。承認待ち・本予約・ほかの第二キープとは重なれない
- 1件の仮予約に重なる第二キープは、承認待ちを含めて1件まで
- 第二キープの占有区間全体に、後からの申込は入れない（仮予約と重ならない部分も含む）
- 重なる仮予約が取消になっても、第二キープの枠は確保されたまま。第二キープのお客様への通知の下書きを作る。お客様の承諾を受けたら、管理者が管理画面で第二キープを仮予約に繰り上げる
- 繰り上げは必ず成功する（第二キープの範囲に、ほかの予約は入れないため）
- お客様が辞退した、または返事がないときは、自動では何もしない。管理画面で警告し、管理者が取消すと枠を解放する
- 重なる仮予約が本予約に昇格したら、第二キープは自動で終了し、枠を解放する。お客様への通知の下書きを作る
- 第二キープが取消・終了して枠を解放したら、第二キープの占有区間の終わりに接して始まる予約が1件あれば、そのお客様に「前倒しできる場合がある」ことを知らせる下書きを作る。実際の前倒しは、予約の変更として管理者が行う

理由：カレンダー上で第二キープを表示し、後からの申込より第二キープを優先するため、第二キープも枠を確保する。承諾を管理者の操作で受けると、お客様向けの操作が増えず、公開APIとINV-3の範囲が広がらない。

### 例

既存の仮予約 P が 13:00–15:00（占有区間 13:00–16:00）の場合の、第二キープの申込。

| 申込 | 結果 |
|---|---|
| 第二キープ 13:00–15:00 | 受付（承認待ち。枠を確保する） |
| 第二キープ 14:00–17:00（占有区間 14:00–18:00） | 受付（Pとだけ重なる） |
| P に第二キープがすでに1件（承認待ちを含む）あるときの、2件目の第二キープ | 不可 |
| 第二キープ 14:00–17:00。ただし 17:00–19:00 に本予約がある | 不可（本予約と重なる） |

さらに、第二キープ K が 14:00–17:00（占有区間 14:00–18:00）で入っている場合の、後からの申込。

| 申込 | 結果 |
|---|---|
| 本予約申込 16:00–18:00（占有区間 16:00–19:00） | 不可（Pとは重ならないが、Kと重なる） |
| 本予約申込 18:00–20:00 | 受付（18:00で接するだけ） |

P と K の出来事。

| 出来事 | 結果 |
|---|---|
| P が取消 → お客様が承諾 → 管理者が繰り上げ | K は仮予約になる |
| P が取消 → 繰り上げ前に 13:00–15:00（占有区間 13:00–16:00）の申込が来る | 申込は不可（Kと重なる）。K はそのまま繰り上げられる |
| P が取消 → K のお客様が辞退 → 管理者が取消 | K は取消。14:00–18:00 の枠を解放する |
| 管理者が P を本予約に昇格 | K は終了。Pと重ならない 16:00–18:00 の枠を解放する（通知の下書きができる） |

前倒しの通知（K は 14:00–17:00、占有区間 14:00–18:00）。

| K の後ろの予約 | K が取消・終了したとき |
|---|---|
| 本予約 18:00–20:00 | 前倒しの通知の下書きを作る（18:00で接している） |
| 本予約 18:30–20:30 | 作らない（接していない） |
| 後ろに予約がない | 作らない |

## 申込フォーム

お客様が入力する項目。外から来るデータなので、APIの境界でスキーマ（Zod）でパースする（INV-4）。

| 項目 | 必須 | 形式 | 補足 |
|---|---|---|---|
| 氏名 | 必須 | 文字列 | |
| 会社名 | 任意 | 文字列 | |
| メールアドレス | 必須 | メールアドレス | |
| 電話番号 | 必須 | 文字列 | |
| 住所 | 必須 | 文字列 | |
| カメラマン氏名 | 必須 | 文字列 | |
| ご利用人数 | 必須 | 1〜14人から選ぶ | 15人以上はフォームでは受けず、問い合わせに案内する（非推奨のため）。管理者が直接入れる |
| 機材保険 | 任意 | 付ける／付けない | 「料金」の節 |
| オプション | 任意 | 複数選択：6人以上のワークショップでの利用／ラメやグリッターを多用した衣装・小道具の持ち込み | 「料金」の節 |
| 予約の種類 | 必須 | 1つ選ぶ：本予約／仮予約 | 仮予約の期限を過ぎた日時では、仮予約は選べない。希望日時が仮予約と重なるときは、第二キープとして申込む（下記） |
| ご希望の利用日時 | 必須 | 開始・終了 | 「時間の単位と利用時間」「申込の締め切り」の節 |
| 撮影内容 | 必須 | 複数選択：スチール撮影／ムービー撮影／楽器の演奏を伴う撮影 | 楽器は「制限あり」。制限の説明を表示するだけで、システムでは判定しない。判断は管理者が承認時に行う |
| 撮影詳細 | 必須 | 自由記述 | |
| ホリゾントの養生 | 必須 | あり／なし | |
| 補足事項 | 任意 | 自由記述 | |
| ホリゾントルールの確認 | 必須 | チェック | チェックしないと送信できない |
| 利用規約への同意 | 必須 | チェック | チェックしないと送信できない |

- プラン（A／B）はお客様に選ばせず、人数から決める。理由：プランと人数の食い違いが起きないようにするため
- 希望日時が承認済みの仮予約と重なり、第二キープの条件（「第二キープ」の節）を満たすときは、フォームで「第二キープとして申込む」ことを案内する。このとき予約の種類は第二キープになる
- お客様の情報は会員とゲストの区別をせず、申込のたびに受け取る

### 例

| 入力 | 結果 |
|---|---|
| 人数 10 | プランA |
| 人数 11 | プランB |
| 人数 15 | 選べない（問い合わせに案内） |
| 利用規約への同意なし | 送信できない |
| 会社名・補足事項が空 | 送信できる |
| 開始 10/20 15:00、送信 10/13 18:00、予約の種類＝仮予約 | 不可（仮予約の期限を過ぎた。本予約なら受付） |
| 希望日時が承認済みの仮予約 P と重なり、P に第二キープがない | 第二キープとして申込める |
| 希望日時が本予約と重なる | 申込めない（空き判定で不可） |

## 料金

### 単価（税抜）

| | 通常帯（8:00〜23:00） | 深夜帯（23:00〜翌8:00） |
|---|---|---|
| プランA（10人以下） | 5,000円/h（30分 2,500円） | 7,500円/h（30分 3,750円） |
| プランB（11人以上） | 5,500円/h（30分 2,750円） | 8,250円/h（30分 4,125円） |

税込で表示するとき：A 通常 5,500円/h・深夜 8,250円/h、B 通常 6,050円/h・深夜 9,075円/h。深夜料金は通常料金の50%増し。

| 追加 | 税抜 | 単位 |
|---|---|---|
| 機材保険 | 1,000円 | 1予約につき1回 |
| オプション：6人以上のワークショップでの利用 | 2,000円 | 1予約につき1回（日付をまたいでも1回） |
| オプション：ラメやグリッターを多用した衣装・小道具の持ち込み | 2,000円 | 1予約につき1回（日付をまたいでも1回） |

### 計算

- 料金をかけるのは予約区間だけ。バッファには料金をかけない
- 予約区間を30分ごとに区切り、それぞれ通常帯か深夜帯かで単価を決める
- 時間料金・機材保険・オプションを税抜で合計し、最後に消費税10%をかけて、1円未満を切り捨てる
- 申込フォームには、入力に応じた見積額（税込）を表示する
- 表示するのは見積額。管理者は承認時に金額を調整（上書き）でき、確認メールで金額を伝える
- 支払いはシステムの外で行う（請求書、または次回利用時にまとめて）。オンライン決済はv1でやらない

理由：税抜で合計してから税をかけると、30分単位で端数が出るBプランの深夜料金でも計算が1通りになり、請求書と揃えやすい。

### 例

| 予約 | 計算（税抜） | 見積額（税込） |
|---|---|---|
| A、10:00–12:00 | 2,500 × 4 = 10,000 | 11,000 |
| A、21:00–翌1:00 | 通常 2,500 × 4 + 深夜 3,750 × 4 = 25,000 | 27,500 |
| B、20:30–翌0:30 | 通常 2,750 × 5 + 深夜 4,125 × 3 = 26,125 | 28,737（28,737.5 を切り捨て） |
| B、00:00–04:00 | 深夜 4,125 × 8 = 33,000 | 36,300 |
| A、10:00–12:00、機材保険、オプション2つ | 10,000 + 1,000 + 2,000 × 2 = 15,000 | 16,500 |
| A、22:00–翌6:00、ワークショップ | 通常 2,500 × 2 + 深夜 3,750 × 14 + 2,000 = 59,500 | 65,450（オプションは1回） |

## 取消とキャンセル料

- お客様からの取消は、システムでは受けない。電話・メールで受け、管理者が管理画面で取消す。理由：刷新後もしばらくは連絡手段を電話・メールに保つため。お客様向けの操作が増えず、公開APIとINV-3の範囲も広がらない
- キャンセル料がかかるのは本予約だけ。承認待ち・仮予約・第二キープの取消は無料
- 率は、管理者が取消を操作した日（JST）が利用日の何日前かで決める（0:00で日付が切り替わる）

| 取消の日 | キャンセル料 |
|---|---|
| 利用日の7日以上前 | なし |
| 6日前〜4日前 | 50% |
| 3日前〜前日 | 80% |
| 利用日当日 | 100% |

- キャンセル料 ＝ 予約の金額（税込の合計。管理者が調整した場合は調整後）× 率。1円未満は切り捨て
- システムは、取消のときにキャンセル料を計算して管理画面に表示し、取消の確認メールの下書きに差し込む。請求はシステムの外で行う

### 例

利用日が 10/20 の本予約、金額 27,500円の場合。

| 取消の日時 | キャンセル料 |
|---|---|
| 10/13 23:59 | なし（7日前） |
| 10/14 00:00 | 13,750円（50%） |
| 10/16 12:00 | 13,750円（50%） |
| 10/17 00:00 | 22,000円（80%） |
| 10/19 23:59 | 22,000円（80%） |
| 10/20 00:00 | 27,500円（100%） |

| ほかの場合 | キャンセル料 |
|---|---|
| 金額 28,737円の本予約を5日前に取消 | 14,368円（14,368.5 を切り捨て） |
| 金額 28,737円の本予約を2日前に取消 | 22,989円（22,989.6 を切り捨て） |
| 自動計算 27,500円を管理者が 25,000円に調整した本予約を当日に取消 | 25,000円 |
| 仮予約を 10/13 17:00 に取消 | なし（仮予約は無料） |
| 10/13 12:00 に本予約へ昇格した予約を、同じ 10/13 の 20:00 に取消 | なし（7日前） |
| 期限を過ぎて仮予約のままの予約を 10/16 に取消 | なし（仮予約は無料） |

## 管理者による予約の直接入力とブロック枠

- 管理者は、電話・メールで受けた予約を、管理画面から直接入れられる
- 管理者は、休業などのブロック枠を管理画面から入れられる。Googleカレンダーの予定も、ブロック枠として取り込む（[index.md](index.md) の「Googleカレンダーの取り込み」）
- 直接入れる予約もブロック枠も、空き判定を通す。既存の予約・ブロック枠と重なるものは入れられない（INV-1）

理由：電話・メールの予約や休業をシステムに入れられないと、ウィジェットからの申込とダブルブッキングになる。管理者が手で予約を管理できる経路も残したい。

### 直接入れる予約のルール

- 承認待ちを経ず、仮予約・本予約・第二キープとして直接入る
- 空き判定（INV-1）と30分単位は、必ず守る
- 締め切り（開始の24時間前）、最短時間（2時間、深夜帯を含むときは4時間）、仮予約の期限に反するときは、警告を出す。管理者が確認すれば入れられる
- 料金の計算は申込と同じ。見積を初期値として表示し、管理者が金額を確定する

理由：電話で「明日入りたい」と言われたときなど、管理者の判断で例外を受けられるようにするため。ダブルブッキングにつながるルールだけは例外を認めない。

### ブロック枠のバッファ

- ブロック枠の占有区間は `[start, end + バッファ)`
- Googleカレンダーから取り込んだブロック枠は、後ろに1時間のバッファを付ける。理由：取り込む予定の多くは電話で受けた実際の予約で、予約の間を1時間空けるルールを守るため
- 管理者が入れるブロック枠は、バッファを「なし／30分／1時間」から選ぶ。初期値は「なし」

### 例

| 操作 | 結果 |
|---|---|
| 10/20 9:00 に、管理者が 10/20 15:00–17:00 の本予約を入れる | 締め切り（24時間前）を過ぎているので警告。確認すれば入る |
| 管理者が 10/20 10:00–11:00 の本予約を入れる | 最短時間（2時間）未満なので警告。確認すれば入る |
| 管理者が、利用日の5日前に仮予約を入れる | 仮予約の期限を過ぎているので警告。確認すれば入る |
| 管理者が 10/20 10:15–12:15 の予約を入れる | 不可（30分単位でない） |
| 管理者が、既存の本予約と重なる予約を入れる | 不可（空き判定） |
| Googleカレンダーの予定 10/20 10:00–12:00 を取り込む | ブロック枠。占有区間は 10:00–13:00 |
| 上のブロック枠があるときに、ウィジェットから 10/20 12:00–14:00 を申込む | 不可（12:00–13:00が重なる） |
| 同じく、ウィジェットから 10/20 13:00–15:00 を申込む | 予約可（13:00で接するだけ） |
| 管理者が休業のブロック枠 10/20 00:00–10/21 00:00 をバッファなしで入れる | 占有区間は 10/20 00:00–10/21 00:00。10/21 00:00–04:00 の申込は予約可 |
| 管理者が清掃のブロック枠 15:00–16:00 をバッファ30分で入れる | 占有区間は 15:00–16:30 |

## 予約の変更

- 変更は管理者が管理画面で行う。お客様からの変更はシステムでは受けない（電話・メールで受ける）
- 変更できるのは、日時（移動・延長・短縮）、人数、オプション、機材保険、そのほかの申込内容
- 日時を変えるときは、変更後の占有区間で空き判定を通す。自分自身の変更前の占有区間は除いて判定する（INV-1）
- 変更前の枠の解放と、変更後の枠の確保は、1トランザクションで行う（INV-2）
- 金額は、変更後の内容で見積を再計算して表示する。キャンセル料（短縮や移動にかかるもの）は自動では計算しない。管理者が金額を確定する
- 状態は変えない（仮予約は仮予約、本予約は本予約のまま）
- 仮予約の期限とキャンセル料の日数は、変更後の利用日で数える
- 変更のとき、お客様への通知の下書きを作る（INV-6）

理由：変更にかかる料金は、事情によって管理者が判断している。決まった計算をシステムに持たせるより、再計算の結果を見て管理者が決める方が、今の運用に合う。

### 第二キープが付いている仮予約の日時を変える

| 仮予約 P の動かし方 | 第二キープ K の扱い |
|---|---|
| 動かしたあとも P と K が重なっている | 何もしない（K は第二キープのまま） |
| 動かしたあと P と K が重ならなくなった | P が取消になったときと同じ扱い。K のお客様への繰り上げ案内の下書きを作り、承諾を受けたら管理者が K を仮予約に繰り上げる。辞退したら管理者が取消す |
| P を、ほかの予約や第二キープがある範囲へ動かす | 不可（空き判定） |

- P を動かすときの空き判定では、K が確保している枠のうち P と重なる部分は、P が使ってよい（K は P の第二キープなので）

### 例

本予約 A が 10/20 10:00–12:00（占有区間 10:00–13:00、金額 11,000円）の場合。

| 変更 | 結果 |
|---|---|
| A を 10:00–13:00 に延長 | 可。占有区間は 10:00–14:00。再計算した見積 16,500円を表示し、管理者が金額を確定する |
| 本予約 B 14:00–16:00 があるときに、A を 10:00–13:00 に延長 | 可（占有区間 10:00–14:00。14:00で接するだけ） |
| 本予約 B 14:00–16:00 があるときに、A を 10:00–13:30 に延長 | 不可（占有区間 10:00–14:30 が B と重なる） |
| A を 11:00–13:00 に移動 | 可（変更前の自分の占有区間とは重なってよい） |
| A を 10/27 10:00–12:00 に移動 | 可。10/20 の枠を解放し、10/27 の枠を確保する（1トランザクション） |
| A を 10/27 に移動したあと、10/22 に取消 | キャンセル料は、利用日 10/27 の5日前として 50% |

仮予約 P が 10/20 15:00–19:00（仮予約の期限は 10/13 18:00）の場合。

| 変更 | 結果 |
|---|---|
| P を 11/10 15:00–19:00 に移動 | 仮予約のまま。期限は 11/03 18:00 になる |

仮予約 P が 13:00–15:00（占有区間 13:00–16:00）、第二キープ K が 14:00–17:00（占有区間 14:00–18:00）の場合。

| 変更 | 結果 |
|---|---|
| P を 13:30–15:30 に移動 | 可。P と K はまだ重なっているので、K はそのまま |
| P を翌日 13:00–15:00 に移動 | 可。P と K が重ならなくなるので、K のお客様への繰り上げ案内の下書きを作る。K の枠は確保されたまま |

## システムでは判定しない運用ルール

今のHPに書かれている運用のうち、v1ではシステムで判定せず、HP・フォームでの表示と管理者の判断で扱うもの。

| ルール | v1での扱い | 理由 |
|---|---|---|
| 仮予約は、1つの利用日につき2日まで押さえられる | HPとフォームに表示する。守られているかは、管理者が承認時に確認する | 「同じお客様」「同じ撮影」をシステムで判定するのは複雑なため |
| 仮予約の枠で本予約したい人がいたら、仮予約のお客様に状況を確認する | 本予約の希望も、第二キープとして申込んでもらう。管理者はそれをきっかけに、仮予約のお客様へ連絡する | 既存の第二キープのルールのまま扱えるため |
| ロケハン（下見）は、撮影の予約が入ると時間を変更することがある | システムの外で扱う（電話・メールで受け、管理者がメモする）。枠は確保しない | 撮影の予約より優先度が低く、枠を確保すると今のルールと逆になるため |

## 確認メール

- 申込を受け付けたら、お客様に定型の受付通知を自動で送る。INV-6 の例外で、人がレビューしたテンプレートだけを使う。予約の成立・金額・空きの可否は書かない（「受け付けました。管理者から連絡します」の趣旨）。理由：今も自動返信を送っており、お客様が申込の到達を確認できるようにするため
- 新しい申込があったら、管理者にメールで知らせる。管理者あてなので INV-6 の対象外。お客様の個人情報は本文に入れず、管理画面へのリンクだけを書く
- 承認・却下・変更・取消のときに、システムが下書きを作る。承認の下書きには金額を、取消の下書きにはキャンセル料を差し込む
- 仮予約の昇格、第二キープの終了、第二キープの繰り上げ案内、前倒しの案内でも下書きを作る
- 受付通知以外のどの下書きも、管理者が内容を確認してから送信する（INV-6）
- お客様へのメールの送信元は `noreply@studiozebra-1st.com`、返信先は `studiozebra1st@gmail.com`（[TECH_STACK.md](../TECH_STACK.md)）

# 予約のデータと状態の移り変わり

予約が何を持ち、どの操作でどの状態に移り、そのとき枠と下書きがどうなるかを1か所にまとめる。
業務のルールそのものは [booking.md](../product-specs/booking.md) にあり、ここはそれを予約のデータと操作の形に直したもの。食い違ったら booking.md が正しい。

関連：[core-beliefs.md](core-beliefs.md)（INV-1、INV-2、INV-6、INV-7、INV-9、INV-10）、[TECH_STACK.md](../TECH_STACK.md)（DynamoDB での重複予約の防ぎ方）

## 予約が持つもの

| 項目 | 中身 | 補足 |
|---|---|---|
| id | 予約を識別する値 | |
| 状態 | `ReservationStatus`（packages/contracts） | 「状態と操作」の節 |
| 予約区間 | 開始・終了 | UTC で保存する（INV-7） |
| バッファ | 60分か30分 | 初期値は60分。管理者が切り替える（booking.md「バッファを30分に縮める」） |
| 経路 | フォームの申込か、管理者の直接入力か | |
| 人数、ホリゾントの養生 | 申込の内容 | プランを決めるのに使う |
| プラン | 料金表のプランの id | 申込（または直接入力・変更）のときに料金表で決めたもの |
| 機材保険、オプション | 有無、料金表のオプションの id | |
| 見積額 | 税抜の合計と税込の見積額（`Yen`） | 申込（または直接入力・変更）のときに、料金表で計算したもの。申込のときの見積は、お客様がフォームで見た金額なので保存し、あとから変えない |
| 確定金額 | 税込（`Yen`） | 承認・直接入力・変更のときに管理者が決める。承認待ちのあいだはない。「金額」の節 |
| 第二キープの仮予約 | 仮予約の id（1件以上） | 承認待ちの第二キープと第二キープだけが持つ。「第二キープと仮予約」の節 |
| お客様の情報 | 氏名、会社名、メールアドレス、電話番号、住所、カメラマン氏名 | 個人情報（INV-10）。会員とゲストを区別せず、予約ごとに持つ（booking.md「申込フォーム」） |
| 撮影の内容 | 撮影内容、撮影詳細、補足事項 | 自由記述の欄は個人情報として扱う（INV-10） |
| 作成日時、更新日時 | | UTC |
| 履歴 | 操作ごとの記録 | 「履歴」の節 |

## 状態と操作

| 操作 | 誰が | 前の状態 → 後の状態 | 枠 | 下書き・通知 |
|---|---|---|---|---|
| 仮予約申込 | お客様（フォーム） | → 承認待ち（仮） | 確保 | 受付通知（自動。INV-6 の例外）、管理者への通知 |
| 本予約申込 | お客様（フォーム） | → 承認待ち（本） | 確保 | 同上 |
| 第二キープ申込 | お客様（フォーム） | → 承認待ち（第二キープ）。重なる仮予約の id を持つ | 第二キープの欄を確保 | 同上 |
| 承認 | 管理者 | 承認待ち（仮）→ 仮予約、承認待ち（本）→ 本予約、承認待ち（第二キープ）→ 第二キープ | 変わらない | 承認の下書き（確定金額を差し込む） |
| 却下 | 管理者 | 承認待ち → 取消 | 解放 | 却下の下書き |
| 昇格 | 管理者 | 仮予約 → 本予約 | 変わらない | 昇格の下書き。この仮予約に付いている第二キープ（承認待ちを含む。ほかの仮予約にも付いているものを含む）は、下の「終了」になる |
| 終了 | システム（昇格に続けて） | 第二キープ・承認待ち（第二キープ）→ 終了 | 第二キープの欄を解放 | 終了の下書き。条件を満たせば前倒しの案内の下書き |
| 取消 | 管理者 | 仮予約・本予約・第二キープ → 取消 | 解放 | 取消の下書き（キャンセル料を差し込む）。仮予約の取消なら、付いている第二キープ（承認済み）に案内の下書き（ほかに付いている仮予約が残っていて、まだ繰り上げられないときは、そのことも伝える）。第二キープの取消なら、条件を満たせば前倒しの案内の下書き |
| 繰り上げ | 管理者 | 第二キープ → 仮予約。仮予約の id をすべて外す | 第二キープの欄から本体の欄へ移す | |
| 変更 | 管理者 | 状態は変えない | 変更前を解放し、変更後を確保する（1トランザクション。INV-2） | 変更の下書き。仮予約を動かして第二キープと重ならなくなったら、その第二キープに繰り上げ案内の下書き |
| バッファの切り替え | 管理者 | 状態は変えない | 確保・解放 | |
| 直接入力 | 管理者 | → 仮予約・本予約・第二キープ（第二キープなら仮予約の id を持つ） | 確保 | |

- 枠を確保・解放する操作は、どれも枠と予約の書き込みを1トランザクションで行う（INV-2）。履歴の書き込みも同じトランザクションに入れる
- 承認は申込どおりに行う。承認で決めるのは確定金額だけ。日時や内容を変えるなら、承認のあとに「変更」として行う（空き判定・履歴・下書きが、変更の流れに乗る）
- 却下は、状態としては取消と同じ。却下か取消かは履歴でわかる
- 繰り上げできるのは、付いている仮予約がすべて、取消になったか動いて重ならなくなった第二キープだけ。お客様の承諾は電話・メールで受け、管理者が操作する（booking.md「第二キープ」）
- 承認待ちのものは自動では失効させない（booking.md「予約の状態」）

## 第二キープと仮予約

- 第二キープ（承認待ちを含む）は、申込（または直接入力）のときに重なっている承認済みの仮予約すべての id を持つ。2件以上の仮予約にまたがってもよい。どの仮予約とも重ならない申込は、第二キープとしては受けない。普通の申込になる
- 1件の仮予約には、占有区間が互いに重ならない第二キープを何件でも付けられる
- 付いている仮予約のどれか1件が本予約に昇格したら、その第二キープは承認待ちも含めて終了する（本予約と重なったままにはしない。INV-1）
- 仮予約が取消になっても、付いている第二キープは状態を変えない。承認済みのものには、1件目の取消から案内の下書きを作る。ほかに付いている仮予約が残っていて、まだ繰り上げられないときは、そのことも伝える。承認待ちのものは承認待ちのまま枠を確保し、管理画面で知らせる。管理者は、承認してから繰り上げるか、却下する
- 仮予約を動かしたときの空き判定では、付いている第二キープの枠のうち仮予約と重なる部分は、仮予約が使ってよい（booking.md「予約の変更」）

## 金額

- 見積額：申込（または直接入力・変更）のときに、料金表で計算する（`calculatePriceFromTable`）。申込のときの見積は保存し、変えない
- 確定金額：承認・直接入力・変更のときに管理者が決める
  - 承認の初期値は、申込のときの見積。今の料金表で計算し直した見積も横に表示し、差があれば知らせる（申込から承認までの間に料金表が変わった場合）
  - 直接入力・変更の初期値は、そのときの料金表での見積
- 料金表が変わっても、確定した予約の金額は変わらない
- キャンセル料は確定金額で計算する（`calculateCancellationFee`）。キャンセル料がかかるのは本予約だけで、本予約は必ず確定金額を持つ

## 履歴

- 予約への操作ごとに1件残す：日時（UTC）、誰が（管理者のユーザー／お客様／システム）、操作（申込・承認・却下・昇格・終了・取消・繰り上げ・変更・バッファの切り替え・直接入力）、変更の前後（状態・予約区間・バッファ・確定金額・第二キープの仮予約）
- お客様の情報や撮影の内容が変わったときは、変わった項目の名前だけを書き、中身は書かない（個人情報を複製しない。INV-10 の考え方）
- キャンセル料の日数で使う「管理者が取消を操作した日」は、取消の履歴の日時（JST）

理由：キャンセル料は取消を操作した日で決まるので、あとから確かめられるようにする。管理者が数人いても、誰が操作したかがわかる。

## まだ決めていないこと

- 取消・終了した予約と履歴を残す期間（booking.md の未決事項「申込で受け取る個人情報の保存期間と削除の方針」）

# Core Beliefs

このリポジトリで常に守る原則。ここに反する変更はマージしない。
ドキュメントで守れないルールは、lint・テスト・CIに昇格させる。

## このプロジェクトの目的

1. **スタジオゼブラで確実に運用を始める** — 実際のお客様の予約を、取りこぼしなく扱えること
2. **AIを主軸にした開発スタイルを試行錯誤する** — 人間は意図とハーネスを書き、コードはエージェントが書く

この2つがぶつかるときは、**本番のお客様に影響する部分では1を優先**する。それ以外では2を優先し、スピードを取る。

## 不変条件

| ID | 内容 | 強制手段 |
|---|---|---|
| INV-1 | **ダブルブッキング禁止。** 承認待ち・仮予約・本予約・第二キープの占有区間（予約区間の後ろのバッファ込み。原則1時間、管理者が予約ごとに30分に縮められる）は互いに重ならない。例外として、第二キープは承認済みの仮予約1件とだけ重なってよい。区間は半開区間 `[start, end)` で扱う | プロパティベーステスト |
| INV-2 | 予約の作成・変更・取消は、枠の確保と予約の書き込みを1トランザクションで行う。途中で失敗したら何も残さない | 統合テスト |
| INV-3 | 公開API（認証なし）は空き状況だけを返す。顧客の個人情報や予約内容は返さない | 契約テスト |
| INV-4 | 外部から来るデータは境界でパースする（Zod）。パース前のデータを内部に流さない | lint / 型 |
| INV-5 | `apps/api` は `apps/site-*` に依存しない。`apps/site-*` が依存できるのは `packages/contracts` と `packages/booking-widget` だけ | 依存関係lint |
| INV-6 | 顧客へのメールは、管理者が内容を確認してから送る（自動送信しない） | 要確認 |
| INV-7 | 日時はUTCで保存し、表示時にAsia/Tokyoへ変換する | lint / テスト（案） |
| INV-8 | コストを増やす構成を入れない：VPC内Lambda（NAT Gateway）、Secrets Manager、保存期間なしのログ、常時起動のリソース | Terraformのポリシーチェック |

## 自律度

壊れたときの痛さで、エージェントにどこまで任せるかを決める。

| レベル | 対象 | エージェントにできること |
|---|---|---|
| 高 | HP・管理画面の見た目、ドキュメント、テストの追加、リファクタリング（不変条件に触れないもの） | 実装からマージまで |
| 中 | 空き判定、予約の作成・変更・取消、料金・キャンセル料の計算、メール本文、公開APIの契約 | 実装とPR作成まで。テスト必須、人間がレビューしてマージ |
| 低 | DBスキーマ・キー設計の変更、本番の `terraform apply`、データの削除・移行、DNS | 変更案（計画とplan結果）の提示まで。実行は人間 |

## 技術判断の原則

- **退屈な技術を選ぶ。** 広く使われていて、エージェントが扱い慣れているものを優先する
- 依存パッケージを追加するときは、理由を PR に書く。小さな機能なら自前で書く方を検討する
- 1つのアプリをローカルでも本番でも同じように起動できること。エージェントがワークツリーごとに起動して検証できる状態を保つ

## 人間の役割

- 何を作るか、何を守るかを決めて、このディレクトリに書く
- エージェントが詰まったら「もっと頑張れ」ではなく、足りないもの（情報、ツール、制約）を探してリポジトリに足す
- 自律度「中」「低」の判断をする
